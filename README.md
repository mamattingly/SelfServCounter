# SelfServ Counter

SelfServ Counter is a React/Vite app served by Express with PostgreSQL persistence, designated user accounts, role-based permissions, and real-time updates.

## Roles
- **Admin:** view/edit shared counts, import CSV, create accounts, assign roles, and delete other accounts.
- **Editor:** view/edit shared counts and import CSV.
- **Viewer:** read-only access.

Public sign-up is disabled. Passwords are bcrypt-hashed. Login sessions are stored in PostgreSQL and use HTTP-only, SameSite=Lax cookies.

## Deploy to Render
1. In Render, choose **New → Blueprint**, connect this repository, and apply `render.yaml`. Review service/database plans and pricing before applying.
2. Set `ADMIN_EMAIL` and `ADMIN_PASSWORD` in the web service environment before the first successful startup. Use a strong password of at least 12 characters. `SESSION_SECRET` is generated by the Blueprint; `DATABASE_URL` is connected from the database resource.
3. Deploy. At first boot the app creates the database tables and initial admin account only if the user table is empty.
4. Sign in as the initial admin and open **User management** to create individual accounts with Admin, Editor, or Viewer access.
5. Share the Render URL. All signed-in users read the same PostgreSQL data; edits are broadcast to connected clients through authenticated server-sent events.

## Existing browser data
The previous version stored values separately in each browser. The server cannot read localStorage remotely. Before switching, export the current list as CSV, sign in to the new server version, and import that CSV once. The database then becomes the shared source of truth.

## Local run
Set `DATABASE_URL`, `SESSION_SECRET` (32+ characters), `ADMIN_EMAIL`, and `ADMIN_PASSWORD` in your shell or a local untracked `.env` file. Run `npm install`, `npm run build`, then `npm start`. The server listens on `PORT` (default 10000). The standalone Vite dev server is not configured as an API proxy.

## Security and operations
Never commit secrets. Create individual accounts rather than sharing credentials. Anonymous API reads and writes are disabled. PostgreSQL backups should be configured in Render; this repository does not configure an automated backup schedule. Deleting a user prevents future authenticated requests, and their existing session is rejected when checked against the database.
